# Sungsimdang Passport · 성심당 패스포트

**Know Before You Go.** Team Avengers · Dongguk University · Enterprise 4.0 and Business Model Innovation.

An unofficial academic MVP connecting a staff shelf-observation simulator, shared inventory, deterministic forecasts, multilingual guidance, Bread Pass and Pilgrim Ledger. Not affiliated with or endorsed by Sungsimdang.

## Run locally

Use Node.js 22.22 or newer (Node 24 LTS also supported by the current dependencies).

```sh
npm install
npm run dev
```

Open the printed local URL, normally `http://localhost:5173/`.

```sh
npm test
npm run build
npm run preview
```

Browser checks (with the development server running):

```sh
npx playwright install chromium
node tests/browser.mjs
node tests/lifecycle-browser.mjs
```

An existing compatible Chromium can be used with `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/absolute/path/to/chromium`. Browser tests reset their own browser-local sample data. No paid API, database or real login is needed.

## Five-minute classroom demonstration

1. **0:00–0:30 — Reset and explain.** Open Demo Mode → Reset. The clock starts at 20 Nov 2026, 10:00 KST. State that all stock, predictions, bookings and rewards are simulations.
2. **0:30–1:15 — Observe and correct.** Operations Center → Main Store → Strawberry Siru Cake → Simulate shelf scan. Set corrected visible count to `2` and backroom to `0`; confirm. Explain that shelf visibility is not total inventory.
3. **1:15–1:45 — Review kitchen advice.** Select Kitchen Planning. Show updated free stock, sell-out and replenishment. Acknowledge; no order is placed.
4. **1:45–2:15 — Ask before traveling.** Open Bakery Assistant, select Strawberry Siru Cake, Main Store and 10:00. Ask “Is strawberry cake available?” Compare the answer with the operations preview. Switch to Korean or Japanese.
5. **2:15–3:00 — Reserve and waitlist.** Bread Pass → Strawberry Siru Cake/Main Store/10:00 → Alex → Reserve. Switch visitor to Mina and join the same slot’s waitlist. Switch to Alex and click Demo: expire. Switch to Mina: a new active QR pass appears.
6. **3:00–3:30 — Controlled transfer.** On Mina’s pass, choose Official transfer → Joon. Confirm. The old pass becomes invalid; a new pass is issued and ₩1,000 is recorded as a simulated donation. No money moves.
7. **3:30–4:15 — Verify and collect.** Switch to Joon. Click Verify pickup → Simulate scanning this QR → enter `333333` → Confirm. If you previously advanced the clock, use a current pickup window or reset first.
8. **4:15–4:40 — Passport.** Open My Passport; see one stamp and the first proposed tourism reward. Open the reward to show its demo limitations.
9. **4:40–5:00 — Business view.** Open Business Dashboard. Show inventory update, expiry, waitlist assignment, transfer, donation and verified pickup. These are demo events, not achieved business results.

Sample phone codes: Alex `111111`, Mina `222222`, Joon `333333`. These are intentionally visible classroom codes, not secure authentication.

## Data and invariants

Three stores, twelve products, three sample visitor profiles. State persists in this browser under `sungsimdang-passport-v3`. Reset removes demo activity and restores fixtures. One active pass per visitor/product; one slot per product/store/window; 30-minute pickup window; one official transfer per pass lineage; one stamp per verified pickup. Reservations allocate inventory, expiry/cancellation releases it, transfer preserves allocation, pickup consumes it. Automatic expiry is triggered by advancing the simulated clock; the demo does not track wall-clock time.

The forecast is deterministic, not trained AI. Percentages are uncalibrated heuristic scores. The assistant uses curated multilingual intents and the same numeric forecast. Glasses overlays are fixtures, not actual detections. Stamps are LocalStorage records, not blockchain assets. QR is generated by a library but scanned through a simulated input action, not a real camera. No real SMS, payments, donations, prices, inventory feeds or partner agreements.

## Known limits

The original business-plan DOCX is missing; six-section traceability is provisional. No real interviews or field evaluation have occurred. No actual computer vision or trained forecast accuracy was measured. Placeholder illustrations are not product photos. Product/store combinations and pass eligibility are examples, not a verified current assortment. LocalStorage is editable and not synchronized across devices; this is not a secure production reservation system. Future dates use the latest snapshot and no replenishment schedule; past snapshots are not reconstructed. Prediction history and real-time operations require a backend in production.
